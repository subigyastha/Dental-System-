Actual Phase 1 risks and required closure work

  1. Update and run the CI ephemeral-PostgreSQL HTTP harness through the new cookie login and CSRF mutation path. Its current request fixture retains bearer authentication as temporary compatibility, so CI does not yet prove cookie/CSRF behavior end to end.
  2. Expose and test the currently implemented session rotation/revoke-all capabilities through approved device/session management controls. Current UI only supports logout of the active session; there is no device list or self-service revoke UI.
  3. Validate production startup secret policy explicitly. A missing AUTH_SECRET is rejected when a production session hash is used, but fail-fast startup validation is not evidenced here.
  4. Run the signed-in, anonymous, API-outage, cookie-CSRF-denial, and cross-clinic browser/API demonstration using synthetic fixtures, then attach redacted evidence below. Browser capture was unavailable during this review.
  5. Before distributed deployment, replace the process-local rate limiter and propagate correlation IDs through structured logs, audit records, traces, and worker boundaries.
