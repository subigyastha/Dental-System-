Manual-review checklist

  • Commit evidence: 4a9b789 introduced persisted cookie sessions, CSRF protection, web transport changes, and removal of web Prisma; a106f91 propagates the verified request session to all current API controllers through request-session.ts. Review that controllers now consume the verified actor rather than reparsing browser credentials.
  • Cookie flow: sign in should yield only the HttpOnly, SameSite=Lax session cookie; the response exposes the user and an in-memory CSRF token, never a session token. Logout must revoke the active session and clear the cookie.
  • Browser transport: confirm requests use credentials: include, unsafe cookie mutations attach x-csrf-token, and browser storage contains neither bearer nor session token. The local authToken state is the literal marker cookie-session, not a credential.

  • Limitations accepted for review: bearer headers remain temporary non-browser compatibility and bypass cookie CSRF; active-session logout is present, but device/session listing and self-service revoke UI are not.
